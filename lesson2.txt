מה זה API?
API (ראשי תיבות של Application Programming Interface) הוא כמו שליח או מגשר שמאפשר לשתי מערכות שונות לדבר זו עם זו, לבקש בקשות ולקבל מידע – בלי ששתיהן צריכות להכיר את כל הסודות הפנימיים אחת של השנייה.

2 דוגמאות מהעולם האמיתי (ללא קשר לתכנות):
מלצר במסעדה:

אתה (הלקוח) יושב בשולחן, והטבח נמצא במטבח.

אתה לא נכנס למטבח לבשל בעצמך, והטבח לא יוצא אליך.

המלצר הוא ה-API: הוא מקבל ממך את ההזמנה (הבקשה), מעביר אותה למטבח, ומחזיר לך את המנה המוכנה (התשובה).

שלט רחוק של טלוויזיה:

אתה רוצה להגביר את הווליום או להחליף ערוץ.

אתה לא פותח את הטלוויזיה ומלחים חוטים בפנים.

השלט הוא ה-API: הוא מספק לך כפתורים פשוטים (ממשק). בלחיצה על כפתור, השלט שולח הוראה מוכנה מראש לטלוויזיה והיא מבצעת אותה.

איך אותו רעיון עובד בפיתוח אתרים (Web Development)?
באתר אינטרנט, ה-API הוא הגשר שמאפשר לפתרונות ולאתרים שונים לתקשר ביניהם בצורה בטוחה ומסודרת:

דוגמה מעשית: כשאת מזמינה מוצר באתר חנות ומגיעה לשלב התשלום, האתר לא מחזיק את כרטיסי האשראי אצלו. הוא פונה דרך API לחברת האשראי, שואל אותה "האם התשלום אושר?", והיא מחזירה לו תשובה של "כן" או "לא".

ה-API מאפשר לאתר לקבל מידע מוכן (כמו מזג אוויר, מפות, או אישור תשלום) ממערכת חיצונית בקלות, בלי לבנות הכל מאפס.

מה ההבדל בין HTML ל-JSON?

HTML (שפת עיצוב והצגה):
מיועדת בשביל בני אדם. היא מתארת ממה הדף מורכב ואיך הוא צריך להיראות על המסך (כותרות, פסקאות, כפתורים ותמונות).

משל פשוט: כמו מכתב מעוצב או ספר. יש בו טקסט, כותרות ועיצוב שהעין שלנו יכולה לקרוא יפה.

JSON (פורמט להעברת נתונים בלבד):
מיועד בשביל מחשבים ותוכנות. הוא מכיל רק את המידע הנקי (נתונים) בצורת מפתח וערך, ללא שום עיצוב, כפתורים או סגנון.

משל פשוט: כמו רשימת מכולת או תעודת זהות. רק עובדות ונתונים יבשים: שם: משה, גיל: 12.

מתי השרת מחזיר כל אחד מהם?

השרת מחזיר HTML כאשר:

הדפדפן מבקש להציג דף אינטרנט שלם למשתמש (למשל כשנכנסים לראשונה לאתר). הדפדפן מקבל את ה-HTML ומצייר את העמוד על המסך.

השרת מחזיר JSON כאשר:

תוכנה או אתר שברקע מבקשים רק את המידע הנקי (בדרך כלל דרך API), בלי לטעון את כל העמוד מחדש. למשל, כשלוחצים על כפתור "רענן רשימה" והאתר רוצה לעדכן רק את הנתונים הקיימים על המסך.

למה נוצר Express?

Express נוצר כדי לחסוך עבודה קשה ולפשט את יצירת השרתים ב-Node.js.

בלי Express, לכתוב שרת באמצעות הרכיב הבסיסי של Node.js (http) זה כמו לבנות בית מלבנים בודדות במו ידיך — זה דורש המון קוד חוזר, מסורבל ומורכב לכל פעולה קטנה. Express מעניק "כלי עבודה מוכנים" שמקצרים את התהליך.

השוואה: שרת ב-http לעומת שרת ב-Express
קריאות הקוד (Readability):

עם http הבסיסי: הקוד ארוך ומלא בתנאים (if/else) כדי לבדוק לאיזה נתיב המשתמש ניסה להגיע (למשל / או /users) ואיזה סוג בקשה זו (GET, POST).

עם Express: הקוד קצר, נקי ומודולרי. מגדירים נתיבים בצורה מאוד ברורה, כמו: app.get('/users', ...) – מיד מבינים מה הקוד עושה.

פרודוקטיביות ומהירות פיתוח (Developer Productivity):

עם http הבסיסי: מפתח צריך לכתוב בעצמו מנגנונים בסיסיים כמו קריאת נתוני JSON, טיפול בקבצים סטטיים, ניהול שגיאות ונתיבים (Routing). זה לוקח זמן יקר ועלול להוביל לטעויות.

עם Express: הכל מוכן ונגיש בשורה אחת או שתיים. Express מטפל אוטומטית בהרבה מהמשימות השגרתיות ומאפשר למפתח להתמקד בבניית הלוגיקה של האפליקציה במקום בבניית התשתיות.

מה זה Route (נתיב) ב-Express?

Route הוא כמו כתובת או שילוט בתוך האתר. הוא מגדיר לשרת מה לעשות ואיזו תשובה להחזיר כאשר המשתמש מנסה להגיע לכתובת מסוימת בדפדפן (בעזרת פעולה מסוימת כמו בקשת GET).

מה הוא מחזיר: קובץ HTML או הודעת ברכה פשוטה שמציגה את עמוד הבית של האתר (למשל: "ברוכים הבאים לאתר!").

מה הוא מחזיר: מערך בפורמט JSON שמכיל את כל המוצרים בחנות (למשל: רשימה של שם מוצר, מחיר ומזהה).

מה זה Module (מודול) ב-Node.js?

מודול הוא פשוט קובץ קוד נפרד שמשמש כמו "קופסת כלים". במקום לכתוב את כל הקוד בקובץ אחד ענקי ומסורבל, מחלקים אותו לקבצים קטנים ושתופסים אחריות על דברים שונים.

איך קובץ אחד משתמש בקוד מקובץ אחר?

קובץ א' מייצא (Export) את הפונקציה או המידע שהוא רוצה לשתף.

קובץ ב' מייבא (Require) את המידע מקובץ א' ומשתמש בו.

‫Gem בהתאמה אישית
השגיאה הזו מופיעה מכיוון שבקובץ package.json שלך מוגדר "type": "module". הגדרה זו אומרת ל-Node.js להשתמש בשיטת import (ES Modules) ולא ב-require.

לפתרון הבעיה יש שתי דרכים (לפי מה שנוח לך):

אפשרות 1: להשתמש ב-import בקוד (מומלץ אם הקובץ package.json כבר מוגדר כ-module)
משנים את שורות ה-require וה-module.exports לשורות של import ו-export default.

בתוך courses.js:

JavaScript
const courses = [
  { id: 1, name: 'פיתוח ב-Node.js', description: 'קורס מקיף לבניית שרתי אינטרנט' },

  { id: 3, name: 'תכנות ב-JavaScript', description: 'למידת שפת התכנות של עולם ה-Web' }

בתוך students.js:

JavaScript
const students = [
  { id: 101, name: 'דוד' },
  { id: 102, name: 'שרה' },
  { id: 103, name: 'רחל' }

בתוך index.js:

JavaScript
import express from 'express';
import courses from './courses.js';
import students from './students.js';

const app = express();
const PORT = 3000;

app.get('/', (req, res) => {
  res.json({
    status: 'success',
    message: 'Welcome to our Express server'
  });
});

app.get('/courses', (req, res) => {
  res.json(courses);
});

app.get('/students', (req, res) => {
  res.json(students);
});

app.listen(PORT, () => {
  console.log(`Server is running on http://localhost:${PORT}`);
});
(שים לב: בשימוש ב-import חובה להוסיף את הסיומת .js בסוף נתיב הקובץ, למשל ./courses.js).

אפשרות 2: להישאר עם require
אם את/ה מעדיף/ה להשתמש ב-require:

פותחים את הקובץ package.json.

מוחקים את השורה "type": "module".

שומרים את הקובץ.

מריצים שוב node index.js.

Gemini נטפרי
‫Gem בהתאמה אישית
הטקסט שמודבק כאן הוא קובץ package-lock.json ולא הקובץ package.json. הקובץ package-lock.json נוצר אוטומטית על ידי Node.js ומכיל רשימה של כל החבילות והגרסאות שהותקנו.

ההגדרה "type": "module" אינה מופיעה בקובץ הזה. היא אמורה להופיע בקובץ בשם package.json (קובץ קצר יותר שנמצא בתיקיית השרש של הפרויקט).

בקובץ package.json היא בדרך כלל מופיעה בחלק העליון, למשל בשורות 5–10:

JSON
{
  "name": "lesson1",
  "version": "1.0.0",
  "type": "module",
  "main": "index.js",
  "scripts": { ... }
}
איך לפתור את זה?

פתח/י את הקובץ package.json (שים/י לב לא לפתוח את package-lock.json).

אם השרת מציג שגיאה על module ובאפשרותך לעבור ל-import, אפשר להוסיף את השורה "type": "module", ישירות מתחת ל-"version".

אם ברצונך להמשיך להשתמש ב-require, יש לוודא שהשורה "type": "module" לא קיימת בקובץ package.json (ואם היא קיימת – למחוק אותה).
