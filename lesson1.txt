1. מה זה Node.js? (הסבר למפתחי Frontend)
בתור מפתחי Frontend (פרונטאנד), אתם רגילים לכתוב קוד JavaScript שמורץ בתוך הדפדפן (כמו Chrome או Firefox). התפקיד של הקוד הזה הוא להנפיש דפים, להגיב בלחיצות כפתור, לנהל טפסים ולעצב את חווית המשתמש.

אז מה זה Node.js?
במילים פשוטות: Node.js הוא סביבת הרצה שמאפשרת להריץ JavaScript מחוץ לדפדפן — למשל, ישירות על המחשב או על השרת (Backend).

אם בעבר JavaScript הייתה "נעולה" רק בתוך הדפדפן, Node.js לקח את מנוע ה-V8 (המנוע שמריץ JS ב-Chrome) והוציא אותו החוצה.

אנלוגיה קטנה:
תחשבו על JavaScript כמו מנוע של מכונית. במשך שנים, המנוע הזה הותקן רק בתוך מכוניות פרטיות (הדפדפן). Node.js לקח את אותו מנוע точно ושם אותו בתוך גנרטור חשמלי (השרת). המנוע עושה את אותה פעולה בסיסית, אבל עכשיו הוא משרת מטרה לגמרי אחרת!

למרות שבשני המקומות כותבים את אותה שפה (JavaScript), הסביבה שבה הקוד רץ מעניקה לו יכולות שונות לגמרי:

השורה התחתונה:
כשאתם מפתחי Frontend, היתרון הגדול של Node.js עבורכם הוא שאתם לא צריכים ללמוד שפה חדשה (כמו Python או Java) כדי לכתוב קוד שרת. אתם משתמשים בדיוק באותה שפת JavaScript שאתם כבר מכירים, רק עם יכולות ועולם תוכן שונה לחלוטין!

הנה דוגמה פשוטה ובסיסית לשימוש ב-Node.js: יצירת שרת אינטרנט קטן שמוציא הודעה למי שנכנס אליו.

בקוד בדפדפן אנחנו רגילים לקבל נתונים משרת. ב-Node.js — אנחנו השרת!

הקוד (קובץ בשם server.js):
JavaScript
// 1. טוענים מודול מובנה של Node.js לתקשורת ברשת (HTTP)
const http = require('http');

// 2. יוצרים את השרת ומגדירים מה יקרה כשמישהו פונה אליו
const server = http.createServer((req, res) => {
  // קובעים שהתשובה תוחזר בפורמט טקסט
  res.setHeader('Content-Type', 'text/plain; charset=utf-8');
  
  // שולחים את ההודעה חזרה
  res.end('שלום! השרת של Node.js עובד בהצלחה!');
});

// 3. אומרים לשרת להקשיב לבקשות בפורט 3000
server.listen(3000, () => {
  console.log('השרת רץ! כנסו בדפדפן לכתובת: http://localhost:3000');
});
איך מריצים את זה?
שומרים את הקוד בקובץ בשם server.js.

פותחים את הטרמינל (שורת הפקודות) במחשב ומריצים:

Bash
node server.js
פותחים את הדפדפן ונכנסים לכתובת http://localhost:3000. רואים את ההודעה שכתבנו!

מה מיוחד פה בהשוואה ל-JavaScript בדפדפן?
שימוש ב-require: ב-Node.js יש גישה לכלים מובנים (כמו מודול ה-http) שלא קיימים בדפדפן.

הקשבה ליציאות (Ports): הקוד מחזיק שרות פתוח במחשב ומחכה שמשתמשים יתחברו אליו.

2. יצירת השרת והגדרת התגובה (createServer)
JavaScript
const server = http.createServer((req, res) => {
  res.setHeader('Content-Type', 'text/plain; charset=utf-8');
  res.end('שלום! השרת של Node.js עובד בהצלחה!');
});
מה זה עושה? הפונקציה createServer בונה את השרת עצמו.

מה זה req ו-res?

req (Request / בקשה): מכיל את כל המידע על מי שפנה אלינו (איזו כתובת הוא ביקש, באיזה דפדפן הוא משתמש וכו').

res (Response / תשובה): הצינור שדרכו אנחנו מחזירים תשובה חזרה לדפדפן.

res.setHeader: מגדיר לדפדפן מה סוג המידע שהוא הולך לקבל (במקרה הזה: טקסט פשוט בעברית).

res.end: שולח את הטקסט הסופי לדפדפן וסוגר את התקשורת.

3. הפעלת השרת והקשבה לבקשות (listen)
JavaScript
server.listen(3000, () => {
  console.log('השרת רץ! כנסו בדפדפן לכתובת: http://localhost:3000');
});
מה זה עושה? השורה הזו אומרת לשרת להתחיל "להקשיב" לפניות שמגיעות למחשב.

מה זה 3000? זה מספק הפורט (Port) – כמו דלת ספציפית במחשב שדרכה השרת מקבל פניות.

ההודעה ב-console.log: ברגע שהשרת עולה בהצלחה, מודפסת הודעה בטרמינל כדי שנדע שהכל מוכן לעבודה.

מה זה npm?
npm פירושו Node Package Manager (מנהל החבילות של Node).

כשפיתחת תכניות או אתרים בעבר, אם רצית להשתמש בקוד שמישהו אחר כבר כתב (למשל: ספריה לעיצוב, כלי לעבודה עם תאריכים, או מנוע לניהול טפסים), היית צריך לחפש אותו באינטרנט, להוריד קובץ ZIP, לחלץ אותו ולשים בתיקיית הפרויקט.

npm פותר את כל הסרבול הזה!

npm מורכב משני חלקים עיקריים:

מאגר קוד ענקי (Registry): ספרייה דיגיטלית ענקית באינטרנט שבה מתכנתים מכל העולם משתפים קוד מוכן (שנקרא "חבילות" - Packages או Modules).

כלי שורת פקודות (CLI): כלי שמגיע מותקן מראש יחד עם Node.js, ומאפשר לך להוריד, לעדכן ולנהל את הספריות האלה ישירות מהטרמינל.

אנלוגיה קטנה:
תחשבו על npm כמו חנות האפליקציות (App Store / Google Play) של עולם ה-JavaScript. במקום לבנות כל אפליקציה/כלי מאפס, אתם נכנסים לחנות, מורידים בלחיצת כפתור (או פקודה קצרה) את מה שאתם צריכים, והמכשיר כבר יודע להפעיל את זה.

איך משתמשים ב-npm בפועל?

התמונה שואלת שאלה מצוינת שמחברת את כל מה שלמדנו עד עכשיו: Why do Node projects have package.json? (למה פרויקטים ב-Node.js צריכים קובץ package.json?).

במילים הכי פשוטות: הקובץ package.json הוא תעודת הזהות ורשימת הקניות של הפרויקט שלכם.

הנה 3 התפקידים המרכזיים שהופכים אותו לקובץ הכי חשוב בכל פרויקט Node.js:

1. תעודת הזהות של הפרויקט
הקובץ מכיל את כל המידע הבסיסי על מה שבניתם. כתובים בו דברים כמו: מה שם הפרויקט, איזו גרסה זו (למשל 1.0.0), מי המפתח שכתב אותו (אתם!), ותיאור קצר של מה הקוד הזה אמור לעשות.

2. "רשימת הקניות" (Dependencies - תלויות)
זוכרים שדיברנו על npm ואיך מורידים דרכו ספריות מוכנות?
ברגע שאתם מורידים ספריה חיצונית, הפרויקט שלכם הופך להיות "תלוי" בה (Dependency) כדי לעבוד. ה-package.json פועל כמו פנקס רישום — הוא מתעד בדיוק אילו ספריות הותקנו ובאיזו גרסה.

למה זה קריטי?
ספריות חיצוניות יכולות לשקול המון. אם תרצו לשתף את הקוד שלכם עם חבר או להעלות אותו לשרת, אתם לא תשלחו את כל תיקיית ה-node_modules הכבדה. אתם תשלחו רק את הקוד שלכם ואת קובץ ה-package.json.
החבר פשוט יפתח את הטרמינל ויכתוב npm install. ברגע זה, npm יקרא את "רשימת הקניות" שבקובץ ויוריד אליו למחשב בדיוק את כל הספריות שצריך, בגרסאות המדויקות!

3. קיצורי דרך לפקודות (Scripts)
בפרויקטים גדולים, הפקודות בטרמינל יכולות להפוך לארוכות ומסורבלות (למשל: הפעלת שרת מיוחד, הרצת בדיקות קוד וכו'). ה-package.json מאפשר לכם להגדיר קיצורי דרך.
למשל, אפשר להגדיר שהפקודה הקצרה והקלה npm start תפעיל מאחורי הקלעים פקודה ארוכה ומורכבת שהגדרתם מראש.

השורה התחתונה: הקובץ הזה עושה סדר. בלעדיו, פרויקט Node.js הוא סתם אוסף של קבצי קוד שלא ברור איך להריץ אותם ומה חסר להם. ה-package.json הופך את הפרויקט למסודר, חכם וקל לשיתוף!

עזרה בפתרון בעיות: הוא יכול להציע פתרונות, להסביר שגיאות בקוד ולהציע שיפורים בזמן אמת בתוך עורך הקוד (VS Code).

מתי עדיף להמתין?
בתהליך למידה: אם אתה בתחילת הדרך, הסתמכות מוקדמת מדי על Copilot עלולה לפגוע בהבנה העמוקה של התחביר והלוגיקה, כי הוא כותב חלק גדול מהקוד עבורך.

שימוש בתשלום: GitHub Copilot הוא שירות בתשלום חודשי (אם כי יש תקופת ניסיון חינם, והוא חינם לסטודנטים ולמפתחי בקוד פתוח מסוימים).

אם המטרה שלך עכשיו היא לתרגל וללמוד לעומק את היסודות של Node.js, מומלץ להמשיך לכתוב את הקוד בעצמך עוד קצת.

התמונה מראה רק שצריך לגשת לכתובת localhost:3000. אם את ניגשת לכתובת הזו בדפדפן ולא מקבלת את רשימת הקורסים, הנה הסיבות האפשריות ואיך לבדוק אותן:

השרת לא פועל: כדי שהדפדפן יוכל להציג משהו מ-localhost:3000, השרת שכתבנו חייב לרוץ ברקע.

הפתרון: פתחי את הטרמינל בתיקיית הפרויקט (lesson1) והריצי: node index.js.

את אמורה לראות בטרמינל הודעה כמו "השרת פעיל בכתובת...".

כל עוד הטרמינל פתוח והפקודה רצה, השרת פעיל.

שגיאה בקוד (קריסה של השרת): גם אם ניסית להריץ את השרת, ייתכן שהוא קרס בגלל שגיאה בקוד (למשל, בעיה עם Chalk או יבוא מודולים). במקרה כזה, השרת מפסיק לעבוד.

הבדיקה: הסתכלי בטרמינל לאחר שניסית להריץ node index.js. אם מופיעה הודעת שגיאה באדום/לבן, השרת לא עובד.

גישה לפורט הלא נכון: ודאי שאת ניגשת בדיוק לכתובת http://localhost:3000 (או לפורט אחר אם הגדרת משהו שונה בקוד תחת const PORT = ...).

הדפדפן מנסה לגשת ל-HTTPS: לפעמים דפדפנים מנסים אוטומטית לגשת ל-https://localhost:3000 (עם s).

הפתרון: הקלידי בשורת הכתובת במדויק: http://localhost:3000 (בלי s).

מה לעשות עכשיו?
במידה והשרת לא פועל עכשיו, פתחי את הטרמינל, נתבי לתיקיית הפרויקט והריצי node index.js. רק אז, רענני את הדף בדפדפן.
